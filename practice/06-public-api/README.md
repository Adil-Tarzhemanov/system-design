# 06 · Публичный API модуля

**Урок 6 — Границы модулей: public API, циклы, линтер**
**~35 минут**

## Ситуация

У сущности `order` есть `index.ts` — то есть публичный API как будто бы есть. Внутри:

```ts
export * from './model/order.ts';
```

Что из этого следует:

- наружу уходит всё, что лежит в `model/order.ts`, — и всё, что там появится завтра;
- то, что снаружи реально нужно (`renderBadge`), через этот файл не проходит вообще;
- поэтому фича лезет внутрь напрямую, двумя разными путями;
- заодно фича нормализует артикул сама — делает работу сущности снаружи от неё.

Отдельно: у самой фичи публичного API нет, и `app` импортирует её внутренний файл.
Правило одинаково для всех слоёв, не только для сущностей.

## Задача

Провести границы явно.

- собрать `entities/order/index.ts` руками: перечислить то, что решено показать;
- завести публичный API у `features/order-list`;
- убрать все импорты, которые пробивают чужой слайс мимо `index.ts`;
- нормализацию артикула вернуть внутрь сущности — снаружи не должно остаться способа
  положить в заказ ненормализованный `sku`.

Ограничения:

- `export *` не использовать нигде;
- сигнатуры `add`, `render`, `total`, `reset` из `app/index.ts` не менять;
- файл с тестами не трогать.

## Проверка

```bash
node --no-warnings --experimental-strip-types --test "practice/06-public-api/**/*.test.ts"
```

Пять тестов: два на поведение (зелёные) и три на границы (красные).

## Сделано, если

- глубоких импортов нет — снаружи в слайс входят только через `index.ts`;
- `export *` не осталось;
- `normalizeSku` не виден снаружи сущности;
- все пять тестов зелёные.

## Что здесь на самом деле отрабатывается

Формулировка, которую стоит унести дословно:

> Публичный API — это то, что я **решил** показать, а не то, что я **забыл** спрятать.

И вторая, про цену: каждый экспорт — это обещание. `export *` раздаёт обещания за тебя,
включая те, которые ты дашь через полгода, дописав функцию в тот же файл. Снять обещание
потом дороже, чем не давать его сейчас: придётся искать всех, кто успел им воспользоваться.

Заметь, чем закончилась история с `normalizeSku`. Глубокий импорт был не причиной, а симптомом:
фича лезла внутрь, потому что сущность не давала ей нужной операции целиком. Так бывает почти
всегда — **дыра в границе означает, что граница проведена не там, где нужна операция.**

Будь готов ответить в чате: **как заставить соблюдать эти границы автоматически, и что
конкретно должен проверять линтер.**
