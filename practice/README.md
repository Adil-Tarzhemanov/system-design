# Практика

Запускаемые упражнения к урокам. В отличие от микро-задачек (те живут в базе и делаются
в голове или текстом) здесь нужно менять код, пока тесты не станут зелёными.

## Как устроено упражнение

```
NN-slug/
  README.md          ситуация, задача, ограничения, «сделано, если»
  src/               стартовое состояние — его и надо чинить
  *.test.ts          контракт упражнения, не редактируется
```

Тесты делятся на две группы:

- **на поведение** — зелёные с самого начала. Их работа — не дать сломать продукт по дороге;
- **на форму зависимостей** — красные. Их работа — не дать назвать рефакторинг законченным,
  пока структура не изменилась на самом деле.

Вторая группа — это не проверка вывода функции, а проверка **графа импортов**:
кто кого знает, есть ли циклы, не идёт ли импорт вверх по слоям, не пробит ли публичный API.
Считает всё это `tools/graph.mjs` — сто с небольшим строк без зависимостей, читается за пять минут.
Заглянуть внутрь полезно: примерно это же делает `eslint-plugin-boundaries` в реальном проекте,
и на собеседовании вопрос «как вы защищаете границы автоматически» звучит регулярно.

## Запуск

Всё сразу — красный список того, что ещё не сделано:

```bash
npm run practice
```

Одно упражнение:

```bash
node --no-warnings --experimental-strip-types --test "practice/03-leaves/**/*.test.ts"
```

## Чего здесь намеренно нет

- **Сборщика и зависимостей.** Только Node 22+. TypeScript исполняется штатным стриппингом
  типов, поэтому синтаксис ограничен стираемым: типы, интерфейсы, `as`, `type`-импорты.
  `enum`, `namespace` и параметры-свойства конструктора работать не будут — и не понадобятся.
- **Проверки типов.** `tsc` не запускается: типы здесь для чтения, контракт задают тесты.
  Красный тип в редакторе — сигнал подумать, но не критерий готовности.
- **Готовых решений на диске.** Разбор — в чате: «готов сдать упражнение 03».
  Ссылки на похожие места у Паромова есть в конце каждого README — они для сверки
  после собственной попытки, а не вместо неё.
