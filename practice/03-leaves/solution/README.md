# Разбор решения · 03-leaves

Это **отдельная копия** упражнения в решённом виде. Исходное состояние лежит рядом,
в `practice/03-leaves/src/` — его я не трогал, сравнивай файл с файлом.

```bash
# решение — все восемь зелёные
node --no-warnings --experimental-strip-types --test "practice/03-leaves/solution/**/*.test.ts"

# исходник — три красных
node --no-warnings --experimental-strip-types --test "practice/03-leaves/leaves.test.ts"
```

## Что было

```
user  →  lib  →  tasks  →  user
```

Кольцо из трёх стрелок. Важное: `user` и `tasks` **напрямую друг друга не импортируют** —
кольцо замыкается через `lib`. Такое не видно глазами на ревью.

## Три стрелки — три разных решения

| # | Стрелка | Что это | Что сделал |
|---|---------|---------|------------|
| 1 | `lib` → `tasks` | **вынужденный** разрыв | убрал: утилита не имеет права знать домен |
| 2 | `tasks` → `user` | **вопрос вкуса** | поднял знание в `app` |
| 3 | `user` → `lib` | **вопрос вкуса** | оставил: кольца нет, стрелка идёт вниз |

Разорвать достаточно одну стрелку, чтобы кольцо перестало быть кольцом. Но задача была
не «сломать кольцо», а «расставить стрелки правильно» — поэтому разрывов два, а не один.

---

## Разрыв 1: `lib` → `tasks` — единственный вынужденный

Было:

```ts
// lib/text.ts
import { countActive } from '../tasks/model.ts';

export function userSummary(userId: string, name: string): string {
  return `${titleCase(name)}: ${countActive(userId)} активных`;
}
```

Здесь нарушено правило из урока: **в нижнем слое не должно быть ни одного слова
из предметной области**. `lib` знает, что бывает пользователь и что у него бывают
активные задачи, — а раз знает, вынужден импортировать домен. Стрелка пошла вверх.

Стало: `userSummary` из `lib` исчез совсем, а его работа разошлась на две части.
Строковая половина осталась внизу:

```ts
// solution/src/lib/text.ts — ни одного импорта
export function titleCase(s: string): string { ... }
export function isBlank(s: string): boolean { ... }
```

Доменная половина уехала наверх, туда, где оба модуля и так видны:

```ts
// solution/src/app/dashboard.ts
export function dashboard(userId: string): string {
  return `${titleCase(rawName(userId))}: ${countActive(userId)} активных`;
}
```

**Почему вынужденный.** У этой стрелки нет варианта «оставить». Пока `lib` знает домен,
он не нижний слой, а значит, любая доменная правка будет трясти утилиты, которыми
пользуются все.

## Разрыв 2: `tasks` → `user` — вопрос вкуса

Было:

```ts
// tasks/model.ts
import { userExists } from '../user/model.ts';

export function addTask(userId: string, title: string): Task {
  if (!userExists(userId)) throw new Error(`нет пользователя ${userId}`);
  ...
}
```

Импорт осмысленный: задача действительно принадлежит пользователю. Проблема не в логике,
а в том, что это **связь между двумя соседями одного уровня** — как раз то, что рано или
поздно замыкается в кольцо.

Здесь работают два приёма из урока, и выбор между ними — настоящий архитектурный выбор.

### Вариант А — поднять знание вверх (выбран)

```ts
// solution/src/tasks/model.ts — ни одного импорта, tasks стал листом
export function addTask(userId: string, title: string): Task {
  const task: Task = { id: `t${++seq}`, userId, title, done: false };
  tasks.push(task);
  return task;
}

// solution/src/app/dashboard.ts
export function createTaskFor(userId: string, title: string): string {
  if (!userExists(userId)) throw new Error(`нет пользователя ${userId}`);
  return addTask(userId, title).id;
}
```

**Плюс:** ноль нового кода, `tasks` становится листом бесплатно.
**Минус, и он настоящий:** `addTask` теперь можно вызвать напрямую и молча создать
задачу несуществующему пользователю. Гарантия переехала из типа в договорённость
«ходи через `app`». Пока `app` — единственная дверь снаружи, это безопасно;
как только модуль начнут дёргать откуда-то ещё, правило потеряется.

### Вариант Б — развернуть через контракт

Если такой размен не устраивает — инверсия из урока 2:

```ts
// tasks/model.ts — тип объявляет сам tasks, реализацию получает снаружи
export type TaskDeps = {
  userExists(id: string): boolean;
};

export function createTasks({ userExists }: TaskDeps) {
  const tasks: Task[] = [];
  let seq = 0;

  function addTask(userId: string, title: string): Task {
    if (!userExists(userId)) throw new Error(`нет пользователя ${userId}`);
    ...
  }
  return { addTask, countActive, completeTask, resetTasks };
}

// app/dashboard.ts
const taskStore = createTasks({ userExists });
```

**Плюс:** гарантия остаётся внутри `tasks`, вызвать его без проверки нельзя в принципе.
`tasks` по-прежнему лист — он не импортирует `user`, только описывает нужную ему форму.
**Минус:** появляется тип, фабрика и подстановка; модуль перестаёт быть набором простых
функций и обзаводится состоянием в замыкании.

**Как выбирать.** Вариант А — когда правило дешёвое и дверь одна. Вариант Б — когда
нарушение правила стоит дорого (деньги, права доступа, целостность данных).
На собеседовании сильный ответ звучит именно так: назвать оба и сказать, по какому
признаку выбирал.

## Разрыв 3: `user` → `lib` — оставлен намеренно

```ts
// solution/src/user/model.ts
import { isBlank } from '../lib/text.ts';
```

После первого разрыва `lib` стал листом и никуда не тянется. Значит, `user` → `lib` —
обычная стрелка **вниз**, в сторону более стабильного модуля. Ровно так и должно быть,
кольца она не создаёт, тесты её не запрещают.

Убирать её стоит только ради жёсткого варианта задачи — «все модули листья».
Цена: `isBlank` придётся либо продублировать в `user`, либо принимать проверку
аргументом. Платить дублированием за связь, которая ничем не мешает, — плохая сделка.

**Вывод, который стоит унести:** цель не «ноль стрелок». Цель — чтобы все стрелки
шли в одну сторону, вниз, в сторону того, что меняется реже.

---

## Что стало

```
        app
      ↙  ↓  ↘
  user  tasks  lib
    ↘         ↙
      (user → lib)
```

- `lib` — лист, знает только строки
- `tasks` — лист, знает только задачи
- `user` — зависит только вниз, на `lib`
- `app` — знает всех, связывает всех, и это его работа

Циклов нет by design: чтобы замкнуть кольцо, нужно пойти вверх, а вверх никто не смотрит.

## Вопрос на разбор

На разборе в чате спрошу именно это: **какой разрыв был вынужденным, а какие два —
вопросом вкуса, и чем ты заплатил за выбранный вариант.** Ответ на разрыв 2 —
про вариант А против варианта Б; ответ на разрыв 3 — про то, почему ноль стрелок
не является целью.
