# 03 · Направление зависимостей и транзитивный цикл

**Урок 3 — Слои и направление зависимостей**
**~40 минут**

## Ситуация

Четыре модуля: `user`, `tasks`, `lib`, `app`. Внешне всё работает — тесты на поведение
зелёные. Внутри — кольцо:

```
user  →  lib  →  tasks  →  user
```

Ни один из трёх модулей нельзя вынуть, понять или протестировать отдельно.
Причём напрямую `user` и `tasks` друг друга не импортируют — они связаны **через посредника**,
и именно такие связи не видно глазами при код-ревью.

## Задача

Развернуть стрелки так, чтобы:

- `lib` не знал ничего о предметной области — только строки;
- `user` и `tasks` не дотягивались друг до друга **ни прямо, ни транзитивно**;
- знание о том, что задача принадлежит существующему пользователю, жило в `app`
  или приходило в `tasks` снаружи — на твой выбор, тест не навязывает;
- поведение четырёх функций из `app/dashboard.ts` осталось прежним до последнего символа.

Файл с тестами не трогать.

## Проверка

```bash
node --no-warnings --experimental-strip-types --test "practice/03-leaves/**/*.test.ts"
```

Восемь тестов: четыре на поведение (сейчас зелёные — их задача не дать сломать) и четыре
на форму зависимостей (сейчас красные).

## Сделано, если

- циклов импортов нет;
- `lib` не дотягивается ни до одного модуля;
- `user` не дотягивается до `tasks`, `tasks` не дотягивается до `user`;
- ни один модуль не импортирует `app`;
- все восемь тестов зелёные.

## Что здесь на самом деле отрабатывается

Два разных умения, которые на собеседовании спрашивают вместе:

1. **Транзитивная зависимость — тоже зависимость.** «У нас модули не импортируют друг друга»
   ничего не значит, если между ними лежит общий `utils`, знающий обе стороны.
2. **Утилита, которая знает домен, — это не утилита.** Самый частый способ построить кольцо
   в реальном проекте: положить в `shared` функцию, которой «удобно» самой сходить за данными.

Будь готов ответить в чате: **какой из трёх разрывов был вынужденным, а какие два — вопросом
вкуса, и чем ты заплатил за выбранный вариант.**
