# Миссия

Пройти собеседование на **middle+ фронтенд-разработчика в казахстанском бигтехе**
(Kaspi, Freedom, Halyk, inDrive, Chocofamily, Beeline) и — что важнее — реально
разбираться в архитектуре, а не заучить формулировки.

## Стартовая точка

- React + TypeScript, ~2–4 года коммерческого опыта
- В архитектуре — новичок. FSD на уровне «читал документацию»
- Есть текстовые расшифровки курса Паромова по FSD (`docs/paromov-lessons/`) — вторичный материал
- Есть его же репозитории с примерами (`../Evgeniy-Paromov/FSD/`) — склад задач и справочник, не второй курс

## Договорённости о курсе

| Решение | Значение |
|---|---|
| Пропорция | 60% system design интервью / 40% архитектура кодовой базы |
| Порядок | Сначала фундамент и код-архитектура, затем проектирование систем |
| Объём | 26 уроков, ~2 часа в день, 6–7 недель |
| Формат | HTML-урок на локальном сервере + разбор в чате |
| Ответы | Только в чате. Оценка 0–5 ставит преподаватель, самооценки нет |
| Память | SQLite + интервальные повторения (SM-2) |
| Практика | Микро-задачки 20–40 минут, без сквозного проекта |
| Примеры | Свои, написанные под курс. Код Паромова — только для сверки после собственного решения |
| Mock-собесы | Каждые 3 урока. Режим жёсткий: перебиваю, требую trade-off, не подсказываю |
| Стек примеров | React + TS + Vite. Next.js — точечно, в уроке 10 и в кейсах |
| Кейсы | Под реальные продукты рынка: маркетплейс, real-time трекинг, финдашборд, чекаут |

## Критерий успеха

На вопрос «расскажи об архитектуре вашего проекта» и на задачу «спроектируй X»
отвечать структурно, с обоснованием каждого решения и с честным называнием того,
чем за это решение заплачено.

## Чего курс НЕ делает

- Не готовит к алгоритмическим секциям
- Не учит вёрстке и CSS
- Не заменяет практику: без микро-задачек знание остаётся книжным
